### 反思1：限制用户输入比程序主题本身更繁琐

**你说得完全对。** 在一个程序中，输入验证的代码量常常超过核心逻辑。这不是你的问题，而是所有程序员的日常：

| 程序核心 | 输入验证 |
|---------|---------|
| `rfact`：3行代码 | `getnumber`：30+行代码 |
| `count`：5行代码 | `get_choice`：20+行代码 |
| 阶乘计算：1行 | 处理 `q`、非法字符、超出范围、多位数字、缓冲区... |

**现实就是如此。** 你接受它，然后习惯它。以后你写商业软件时，输入验证通常占程序总代码量的 40%-60%。

---

### 反思2：循环重新开始前一定要把所有内容重置

**你已经亲身经历过这个错误了。** 下次你再写类似函数时，你会**自动**检查"重置了吗？"——这就是经验的形成。

你可以养成一个习惯：**在写 `continue` 之前，列一个清单，写下所有需要重置的变量。**

```
// continue 之前：
// num = 0
// 缓冲区已清空
// 不需要重置 input1，因为马上会重新读取
```

---

### 反思3：多位数字的组装算法我完全想不到，怎么办

**这个算法不是"想出来"的，是"学来的"。**

`num = num * 10 + (ch - '0')` 是一个**已知的编程模式**，就像 `for (i = 0; i < n; i++)` 一样。你不知道它，只是因为你还没见过它。现在你见过了，它就进入了你的工具箱。

**以后你遇到类似问题，就会想起这个模式：**
- 从字符串中提取数字 → `num * 10 + digit`
- 从 ASCII 字符转数字 → `ch - '0'`
- 多位数字组合 → 从左到右累乘

## 给想不出算法的你

想不出算法是**正常的**，因为算法不是凭空产生的，而是**经验积累的结果**。

| 阶段 | 状态 |
|------|------|
| 初学者 | 没见过任何算法，遇到问题完全空白 |
| 现在你 | 见过 `num*10+digit`，下次会想起来 |
| 未来 | 见过几十个算法，遇到问题能联想到相似模式 |

**这不是"想不想得到"的问题，是"见没见过"的问题。** 你见过，就会了。
